一、SQL 基础面试题

1. 一张表有 n 条数据，如何取第 10 到 20 条？
答案：使用 LIMIT 分页。
SELECT * FROM 表名 ORDER BY id LIMIT 9, 11;
注意：LIMIT后第一个参数是偏移量（从0开始），取第10条开始偏移量是9，取11条就是10到20。
深分页性能优化：用WHERE id > 上次最大id LIMIT 11。

2. WHERE 和 HAVING 的区别？
答案：
（1）作用时机不同：WHERE在分组前过滤行，HAVING在分组后过滤组。
（2）使用条件不同：WHERE中不能用聚合函数，HAVING中可以用。
（3）执行顺序：WHERE → GROUP BY → HAVING。

3. COUNT(*)、COUNT(1)、COUNT(列名) 的区别？
答案：
COUNT(*)：统计所有行数，包括NULL行，性能最优。
COUNT(1)：与COUNT(*)性能基本一致。
COUNT(列名)：统计该列非NULL的行数，会跳过NULL。
InnoDB中COUNT(*)会选择最小的二级索引遍历，比COUNT(主键)快。

4. DROP、DELETE、TRUNCATE 的区别？
答案：
DELETE：DML语句，逐行删除，可带WHERE，可回滚，速度慢，自增不重置。
TRUNCATE：DDL语句，清空整表，不可带WHERE，不可回滚，速度快，自增重置。
DROP：DDL语句，删除整个表（结构+数据），不可回滚。
速度：DROP > TRUNCATE > DELETE。

5. UNION 和 UNION ALL 的区别？
答案：
UNION：合并结果集后去重，需要排序，性能较差。
UNION ALL：合并结果集不去重，性能更好。
如果业务不需要去重，一律用UNION ALL。

二、索引面试题

6. 为什么要用索引？有什么优缺点？
答案：
优点：大幅提升查询速度，降低数据扫描行数。
缺点：
（1）索引本身占存储空间。
（2）降低写入速度（INSERT/UPDATE/DELETE需要维护索引）。
（3）索引不是越多越好，需要精心设计。

7. 索引的底层数据结构是什么？为什么用 B+ 树？
答案：InnoDB默认使用B+树索引。
原因：
（1）B+树非叶子节点不存数据，一个页能存更多索引键，树更矮，磁盘IO少。
（2）叶子节点用双向链表相连，范围查询效率高。
（3）所有查询都走到叶子节点，性能稳定。
对比：哈希索引只支持等值查询，不支持范围和排序；二叉树树太高；B树叶子节点不相连，范围查询慢。

8. 聚簇索引和非聚簇索引的区别？
答案：
聚簇索引：数据行按主键顺序存储，叶子节点直接存整行数据，一张表只有一个。
非聚簇索引（二级索引）：叶子节点存主键值，查询时需要回表。
回表：先在二级索引查到主键值，再到聚簇索引查整行数据的过程。
覆盖索引：查询的列都在二级索引中，不需要回表，性能最优。

9. 什么是最左前缀原则？
答案：联合索引(a,b,c)相当于建立了(a)、(a,b)、(a,b,c)三个索引。
查询必须从最左列开始匹配，不能跳过中间列。
能命中：WHERE a=1、WHERE a=1 AND b=2、WHERE a=1 AND b=2 AND c=3。
不能命中：WHERE b=2、WHERE c=3、WHERE b=2 AND c=3。
范围查询后面的列无法使用索引。

10. 哪些情况下索引会失效？
答案：
（1）对索引列使用函数或运算：WHERE DATE(create_time)='2024-01-01'。
（2）隐式类型转换：字符串列用数字查询。
（3）LIKE以%开头：WHERE name LIKE '%张三'。
（4）违反最左前缀原则。
（5）OR两边有一边没有索引。
（6）使用 != 或 <>。
（7）NOT IN、NOT EXISTS。
（8）优化器评估全表扫描比走索引更快时。

11. 怎么建索引？建索引的原则？
答案：
（1）WHERE、JOIN、ORDER BY、GROUP BY涉及的列建索引。
（2）区分度高的列适合建索引（如性别区分度低，不适合）。
（3）优先建联合索引，而非单列索引。
（4）尽量扩展覆盖索引，避免回表。
（5）索引不是越多越好，控制在5个以内。
（6）大字段不建索引，或前缀索引。

三、事务面试题

12. 事务的 ACID 是什么？
答案：
原子性（Atomicity）：事务内操作要么全成功要么全回滚，由undo log实现。
一致性（Consistency）：事务前后数据保持一致状态，由其他三个特性共同保证。
隔离性（Isolation）：并发事务之间互不干扰，由锁和MVCC实现。
持久性（Durability）：事务提交后修改永久保存，由redo log实现。

13. 并发事务会带来什么问题？
答案：
脏读：读到其他事务未提交的数据。
不可重复读：同一事务内两次读同一行结果不同（被其他事务UPDATE提交）。
幻读：同一事务内两次查询行数不同（被其他事务INSERT/DELETE提交）。

14. 事务隔离级别有哪些？
答案：
读未提交（READ UNCOMMITTED）：什么问题都不解决。
读已提交（READ COMMITTED）：解决脏读。
可重复读（REPEATABLE READ）：解决脏读、不可重复读，InnoDB默认级别。
串行化（SERIALIZABLE）：解决所有问题，性能最差。
MySQL默认是RR级别，InnoDB通过MVCC+间隙锁解决了幻读。

15. MVCC 是什么？原理？
答案：MVCC（多版本并发控制）通过保存数据的多个版本，实现读写不阻塞。
实现三要素：
（1）隐藏列：trx_id（最近修改事务ID）、roll_pointer（指向undo log旧版本）。
（2）undo log版本链：每次修改都记录旧版本，串成链表。
（3）Read View：事务启动时生成的读视图，记录活跃事务ID，判断哪个版本可见。
RR级别下事务启动时生成Read View，RC级别下每次SELECT都生成新Read View。

16. 隔离级别 RR 和 RC 的区别？
答案：
RC（读已提交）：每次SELECT都生成新Read View，能读到其他事务已提交的新数据，不可重复读。
RR（可重复读）：事务启动时生成一次Read View，整个事务期间复用，保证可重复读。
RC在主从复制STATEMENT格式下可能导致主从不一致，生产常用RC。

四、锁面试题

17. MySQL 有哪些锁？
答案：
按粒度：表锁、行锁、页锁。
按性质：共享锁（S）、排他锁（X）。
InnoDB行锁类型：
记录锁：锁单行。
间隙锁：锁索引间隙，防止幻读。
临键锁：记录锁+间隙锁，默认算法。

18. 什么时候行锁会退化成表锁？
答案：
（1）查询没有用到索引，InnoDB只能全表扫描，锁所有行。
（2）索引失效时。
（3）使用LOCK TABLES显式加表锁。

19. 什么是死锁？怎么避免？
答案：两个事务互相持有对方需要的锁，循环等待。
避免：
（1）按相同顺序访问表和行。
（2）大事务拆小。
（3）为查询加索引，减少锁定行。
（4）降低隔离级别。

五、SQL 优化面试题

20. 怎么优化慢查询？
答案：
（1）开启慢查询日志，定位慢SQL。
（2）用EXPLAIN分析执行计划，看type、key、rows、Extra。
（3）加合适索引，避免全表扫描。
（4）避免SELECT *，只查需要的列。
（5）优化深分页，用延迟关联或游标分页。
（6）小表驱动大表。
（7）避免在索引列上做函数运算。
（8）数据量大时考虑分库分表。

21. EXPLAIN 重点看哪些字段？
答案：
type：访问类型，ALL最差，const最好，至少要达到range/ref级别。
key：实际用到的索引，NULL表示没走索引。
rows：预估扫描行数，越小越好。
Extra：
Using index：覆盖索引，好。
Using where：服务器层过滤。
Using filesort：额外排序，需优化。
Using temporary：临时表，需优化。

22. 深分页怎么优化？
答案：原始SQL：SELECT * FROM orders ORDER BY id LIMIT 100000, 10;
问题：扫描前10万行丢弃，效率低。
优化1（延迟关联）：
SELECT o.* FROM orders o JOIN (SELECT id FROM orders ORDER BY id LIMIT 100000, 10) t ON o.id = t.id;
优化2（游标分页）：
SELECT * FROM orders WHERE id > 上次最大id ORDER BY id LIMIT 10;

六、其他高频题

23. 内连接和外连接的区别？
答案：
内连接（INNER JOIN）：只返回两表匹配成功的行。
左外连接（LEFT JOIN）：返回左表所有行，右表匹配不到显示NULL。
右外连接（RIGHT JOIN）：返回右表所有行，左表匹配不到显示NULL。
全外连接（FULL OUTER JOIN）：MySQL不支持，可用LEFT JOIN UNION RIGHT JOIN模拟。

24. 什么是视图？用视图有什么好处？
答案：视图是一张虚拟表，本质是保存的SQL查询。
好处：
（1）简化复杂查询。
（2）权限控制，只暴露部分列给用户。
（3）数据独立，基表结构变化不影响视图。
注意：视图不提升查询性能，复杂视图嵌套反而可能变慢。

25. 主键和唯一索引的区别？
答案：
（1）主键一张表只能有一个，唯一索引可以有多个。
（2）主键不允许NULL值，唯一索引允许NULL。
（3）主键默认是聚簇索引，唯一索引默认是非聚簇索引。
（4）主键名固定PRIMARY，唯一索引可自定义名称。

26. MySQL 主从复制原理？
答案：
（1）主库将变更写入Bin Log。
（2）从库IO线程拉取Bin Log写入Relay Log。
（3）从库SQL线程重放Relay Log，同步数据。
解决的问题：读写分离、数据备份、高可用。
主从延迟原因：单线程重放、大事务、网络延迟、从库性能差。

27. Redis 能替代 MySQL 做持久存储吗？
答案：不能。
原因：
（1）Redis是内存数据库，虽然有RDB/AOF持久化，但不能保证不丢数据。
（2）Redis不支持复杂查询和事务。
（3）内存成本远高于磁盘。
Redis适合做缓存，MySQL做持久存储，两者配合使用。

28. 为什么用 utf8mb4 而不是 utf8？
答案：MySQL的utf8是3字节编码，不支持emoji等4字节字符。
utf8mb4是4字节完整UTF-8编码，支持所有Unicode字符。
MySQL5.5之后才有utf8mb4，生产环境一律用utf8mb4。
